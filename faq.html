FAQ / QUICK ANSWERS

Clear answers. No inflated claims.

What PPSX33 aims to do, what its inputs mean and how to interpret progress.

What is PPSX33?

An experimental PlayStation 3 full recompiler with a native C++ / Qt 6 desktop application. It lifts supported code from decrypted ELF input into native Windows builds and uses a modular runtime. PPU, HLE, SPU/MFC/DMA and RSX/GCM behavior remain partially implemented, so general compatibility is not established.

Is PPSX33 a finished emulator?

No. It is an experimental full recompiler, not a finished emulator. A successful lift, compile, window or diagnostic render does not establish game compatibility.

What input does it expect?

Decrypted ELF input. It is not a retail decryption utility and does not distribute game files, firmware or keys.

Can I search for PS3 games here?

Yes. The Wiki searches Wikipedia's public API. Those results are background information, not compatibility ratings.

Does a Wikipedia result mean PPSX33 supports a game?

No. Compatibility requires reproducible PPSX33 tests and documented outcomes.

Why is compile success not enough?

The current roadmap tracks PPU recovery, null-loop and soft-break behavior, FIFO GET/PUT correctness, guest PUT progress without boot assist, and title-authored draws and shaders. The desktop frontend has moved to Qt 6, but a working interface or successful build does not prove game compatibility.

Why isn't a diagnostic triangle proof of rendering?

It tests the host graphics path. Real title rendering also requires guest command submission, resources, shaders and synchronization. Boot-assist command streams are diagnostic probes only.

Where is current status?

Check the core repository roadmap, source code, tests and commit history.

How can I help?

Reproduce a clearly described issue, share useful logs and tests, or improve documentation. Use software and data you are legally entitled to access.

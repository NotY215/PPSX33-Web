ARCHITECTURE / SYSTEM MAP

From guest executable to host execution.

The application is a native C++ / Qt 6 Widgets desktop frontend. ps3core.dll provides ELF/project processing and PPU lifting; the generated game executable links with ps3rt.dll and its graphics modules. Source responsibilities are separated across src/core, src/processor, src/RSX, src/games-stuff and the desktop UI. Vulkan 1.2 is the default host graphics path, OpenGL parity is in progress, and Direct3D 11 has been removed. Each stage has its own assumptions, failure modes and validation requirements.

02 / SUBSYSTEMS

Boundaries that must agree

CPU

PPU and generated code

Instruction decoding and lifting, branches, CR/LR/CTR/XER, memory, floating point and VMX. Translation counts do not prove semantic correctness.

OS

Runtime and HLE

Guest address space, import/NID dispatch, LV2, PRX, threads, files, audio, input and saves. These services remain partial and need module-level and title-level tests.

SPU

SPU / MFC / DMA

Execution state, DMA tags, completion order, channels and synchronization.

GPU

RSX / GCM

FIFO GET/PUT progress, command decoding, resources, textures, render targets, shader translation and presentation. Assist draws validate only the host graphics path, not title-authored rendering.

HOST

Native platform

Qt 6 desktop workflow, build configuration, graphics backend, windowing, paths and diagnostics.

QA

Validation

Focused tests, strict faults, reproducible logs and per-title outcomes.

03 / DEBUGGING

Trace failures from the earliest boundary. The immediate critical path is PPU recovery around sticky PCs and import islands, honest null-loop/soft-break handling, FIFO GET/PUT correctness, guest PUT progress without boot assist, then title-authored draws and shaders. The Qt Qt 6 desktop frontend can rebuild selected render modules without re-lifting the game executable.
